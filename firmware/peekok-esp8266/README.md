# 피콕 로봇 몸체 — ESP8266 펌웨어

ESP8266(NodeMCU · Wemos D1 mini)이 WiFi 로 배달 서버에 붙어, 검정 라인을 따라 노드(교차로)를 지나며 목적지까지 달립니다.
서버와 주고받는 규약은 [../../docs/robot-api.md](../../docs/robot-api.md) 를 보세요.

## 준비물 (기본 구성)

| 부품 | 예 | 메모 |
| --- | --- | --- |
| 보드 | NodeMCU 1.0 (ESP-12E) 또는 Wemos D1 mini | |
| 모터 드라이버 | L298N · L9110S · MX1508 (입력 4개) | L298N 은 ENA/ENB 점퍼를 꽂은 채로 |
| 모터 | DC 기어드 모터 2개 (좌·우 바퀴) | 앞이나 뒤에 보조 바퀴 |
| 라인 센서 | 적외선 반사 센서 3개 (TCRT5000 모듈 등) | 가운데 1개는 선 위, 양쪽은 선 바로 바깥 |
| 전원 | 모터용 배터리 + 보드용 5V | 모터 드라이버와 보드의 GND 를 꼭 연결 |

## 배선 (config.h 에서 바꿀 수 있음)

| 보드 핀 | 연결 |
| --- | --- |
| D1 | 모터 드라이버 IN1 (왼쪽 모터) |
| D2 | 모터 드라이버 IN2 (왼쪽 모터) |
| D5 | 모터 드라이버 IN3 (오른쪽 모터) |
| D6 | 모터 드라이버 IN4 (오른쪽 모터) |
| D7 | 라인 센서 왼쪽 OUT (디지털) |
| D0 | 라인 센서 가운데 OUT (디지털) |
| A0 | 라인 센서 오른쪽 OUT (아날로그로 읽어 문턱값 비교 — ESP8266 은 디지털 핀이 모자람) |
| D3 | 보드의 FLASH 버튼 (엘리베이터에서 내린 뒤 누르기) — 따로 버튼을 달려면 D3 ↔ GND |
| D4 | 보드 내장 LED (상태 표시) |

D3·D4·D8 은 켤 때 상태가 정해져 있어야 하는 핀이라 센서·모터에 쓰지 않았습니다.

## 올리기 (Arduino IDE)

1. 파일 → 환경설정 → 추가 보드 관리자 URL 에 `https://arduino.esp8266.com/stable/package_esp8266com_index.json`
2. 보드 매니저에서 **esp8266** 설치 → 보드 **NodeMCU 1.0 (ESP-12E Module)** 또는 **LOLIN(WEMOS) D1 R2 & mini**
3. 이 폴더의 `config.example.h` 를 복사해 **`config.h`** 로 저장하고 WiFi 이름·비밀번호, 로봇 키(Cloudflare `ROBOT_KEY` 와 같은 값)를 채웁니다.
   `config.h` 는 저장소에 올라가지 않습니다.
4. `peekok-esp8266.ino` 를 열고 업로드. 시리얼 모니터 115200.

추가 라이브러리는 필요 없습니다 (ESP8266 보드 패키지에 들어 있는 WiFi · HTTPClient · BearSSL 만 사용).

## 맞추기 (시리얼 모니터에 한 글자 입력)

| 입력 | 하는 일 |
| --- | --- |
| `s` | 센서 값 5초 동안 보기 — 검정 선 위에서 1 이 나오면 `LINE_IS_HIGH 1`, 0 이면 `0`. 오른쪽(A0) 은 숫자를 보고 `RIGHT_ANALOG_THRESHOLD` 조정 |
| `f` | 1초 앞으로 — 뒤로 가는 바퀴가 있으면 `LEFT_INVERT` / `RIGHT_INVERT` 를 1 로 |
| `l` / `r` | 제자리 왼쪽 / 오른쪽 회전 |
| `c` | 5초 동안 라인 따라 직진 → 간 거리(m) ÷ 5 를 `ROBOT_SPEED_MPS` 에 넣기 (위치 표시와 마지막 구간 멈춤에 쓰임) |
| `p` | 받은 주행 계획 보기 |
| `x` | 멈춤 |

교차로에서 너무 일찍/늦게 돌면 `TURN_FORWARD_MS`, 교차로를 못 지나가면 `CROSS_CLEAR_MS` 를 바꿉니다.

## 달리는 방식

1. 1.5초마다 `GET /api/robot/drive` 로 모드와 계획을 확인합니다.
2. 모드가 `to_caller` · `delivering` · `returning` 이면 출발:
   - 처음에는 켤 때 방향(`HOME_HEADING`)과 계획의 첫 방향을 비교해 그대로 가거나 유턴합니다.
   - 라인을 따라가다 교차로(센서 양쪽이 함께 검정)를 만나면 멈추고 `progress` 로 보고한 뒤,
     서버가 정해 준 동작(좌회전·우회전·직진·유턴)을 합니다. 다음 노드까지 예상 시간의 45% 가 지나기 전 교차로 신호는 무시합니다.
   - **엘리베이터 노드**에서는 멈춰 기다립니다. 로봇 화면에 "엘리베이터에 태워 주세요" 가 뜨면 사람이 로봇을 태워
     해당 층에서 내려 출구 방향으로 선 위에 놓고, **FLASH 버튼** 또는 **로봇 화면의 "N층에서 내렸어요"** 를 누르면 이어서 달립니다.
   - 마지막 노드를 지나면 `END`(방 문 앞)까지는 거리 ÷ 속도 시간만큼 가서 멈추고 `arrived` 를 보냅니다.
3. 달리는 중 보고 응답에서 계획이 바뀌면(취소·새 목적지) 멈추고 새 계획으로 다시 출발합니다.

LED: 천천히 깜빡 = 대기 · 켜짐 = 주행 · 0.5초 깜빡 = 엘리베이터 대기 · 빠르게 깜빡 = 오류(선을 잃음 등, 새 계획이 오면 다시 시도)

## 보안 메모

HTTPS 인증서 검사를 하지 않는 간단한 방식(`setInsecure`)으로 접속합니다. 학교 WiFi 안에서 쓰기에는 충분하지만,
더 안전하게 하려면 BearSSL 의 신뢰할 인증서(예: Google Trust Services / Let's Encrypt 루트)를 넣고 NTP 로 시간을 맞춘 뒤 `setTrustAnchors` 를 쓰세요.
로봇 키가 새면 Cloudflare 에서 `ROBOT_KEY` 를 바꾸고 `config.h` 와 태블릿 설정 링크를 새 값으로 바꾸면 됩니다.

## 시험

실제 로봇 없이 같은 방식으로 서버와 주고받는 시뮬레이터:

```bash
node tools/robot-sim.js --base https://kis-peekok.pages.dev --key <로봇 키> --text --fast 5
```
